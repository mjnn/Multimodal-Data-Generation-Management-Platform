# M10 · Taxonomy 语义中枢 — UI/UX 方案对比

| 字段 | 内容 |
|------|------|
| 里程碑 | M10 |
| 页面 | `/taxonomy` Hub、全局契约条、数据集/校核/管线嵌入 |
| 前置 | `docs/m10-implementation-notes.md` §5 |

---

## 设计简报

**用户主张**：标签树是平台精髓；打标、校核、数据集、场景挖掘都应围绕 **Taxonomy 版本契约** 展开。

**必须可见的信息**：

1. 当前 **published** 是哪一版  
2. 本页/本对象绑定的 **taxonomy version**  
3. 数据对树的 **覆盖率 / 缺口**  
4. 版本 **diff / 影响面**（publish 前）  
5. **提案队列**（数据驱动完善，不自动改树）

**角色**：admin 编辑+发布；reviewer 看契约+提交提案（可选 M10.8）；dataset_manager 锁定契约+看分布。

---

## 方案 A · Hub 优先（「语义中心」）

**风格**：Taxonomy 升为一级产品首页级模块；侧栏「标签树」带 published 角标。

**布局**：

```text
┌─────────────────────────────────────────────────────────┐
│ [侧栏] 标签树 ● v2 published                             │
├─────────────────────────────────────────────────────────┤
│  Tab: 版本时间线 | 数据洞察 | 提案队列                    │
│  ┌──────────────┬──────────────────────────────────┐  │
│  │ 版本 DAG     │  选中版本：diff / impact / 编辑    │  │
│  │ v1 → v2 → v3 │  覆盖率热力表（label_id × enum）    │  │
│  └──────────────┴──────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

| 优点 | 缺点 |
|------|------|
| 存在感最强，符合「树是精髓」 | 与其他页跳转多，需强 deep link |
| 洞察/diff/提案集中 | 首屏信息密度高，需良好 Tab 划分 |

**Tokens**：专业 B2B；主色沿用现有 Ant Design；洞察 Tab 用热力表格 + 进度条。

---

## 方案 B · 上下文徽章（「契约随行」）

**风格**：侧栏不变；**每条业务流顶栏**固定 `TaxonomyContextBar`（published + 本页契约 + 覆盖率摘要链接）。

**布局**：

```text
校核工作台
┌─────────────────────────────────────────────────────────┐
│ 🌳 契约 label_tree_baseline (v2) · 本 Clip v2 · [洞察↗]  │
├─────────────────────────────────────────────────────────┤
│  （现有校核表单）                                          │
└─────────────────────────────────────────────────────────┘
```

Hub 保持现有 `/taxonomy` 列表+编辑器，**增量**「洞察」「提案」两个 Tab，不做 DAG 大图。

| 优点 | 缺点 |
|------|------|
| 改动面可控，各页立刻「有关联」 | Hub 存在感弱于 A |
| 符合「在哪工作都能看见契约」 | diff/lineage 仍要进 Taxonomy 页 |

**Tokens**：紧凑 32px 高 context bar；warning 色表示契约 ≠ published。

---

## 方案 C · 双轨（Hub + 抽屉）

**风格**：方案 B 的 context bar + 任意页点击「打开 Taxonomy 抽屉」侧边 480px 预览树/节点定义/覆盖率，不全页跳转。

| 优点 | 缺点 |
|------|------|
| 校核时不离开工作台 | 抽屉内 diff/提案队列空间不足 |
| 适合频繁查定义 | 实现复杂度最高 |

---

## 对比表

| 维度 | A Hub 优先 | B 徽章随行 **(推荐基底)** | C 双轨抽屉 |
|------|------------|---------------------------|------------|
| 标签树存在感 | ★★★★★ | ★★★☆ | ★★★★ |
| 实施成本 | 中高 | 中 | 高 |
| 校核体验 | 需跳转 | 顶栏即见 | 最好 |
| diff/洞察深度 | 最好 | 好（Hub Tab） | 中 |
| 与现有 UI 兼容 | 中改 | **最小侵入** | 中改 |

---

## 推荐组合 · **A− + B**（R-UI-M10-1 建议）

1. **全局 + 业务页**：采用 **方案 B** `TaxonomyContextBar`（校核 / 数据集 / 管线 / 总览）。  
2. **Taxonomy 页**：采用 **方案 A 的 Tab 结构**（版本线 + 数据洞察 + 提案），但 **不** 改侧栏 IA 顺序。  
3. **M10 不做** 方案 C 全站抽屉（留给 M11 若需要）。

请确认是否采纳 **A−+B**，或指定组合（如纯 A / 纯 B）。
